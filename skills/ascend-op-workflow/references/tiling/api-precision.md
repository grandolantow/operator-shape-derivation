# API、别名与数值路径的适用边界

用于当前方案依赖 Cast、近似数学、in-place、归约索引或 dtype 转换时。知识卡提示设计风险，实际行为以目标 CANN/编译器/SoC 的重载、RoundMode、dtype 和接口说明为准；不复制历史实验通过率作为通用规则。

## 区分依据

| 依据 | 可得出的结论 | 边界 |
|---|---|---|
| 目标 SDK/官方文档明确支持 | 可在相同版本和支持域内作设计依据 | 不能跨重载、dtype 或平台推广 |
| 受控试验观察 | 该候选、输入和环境中的行为 | 保留覆盖范围，不能升级成硬件规格 |
| 数学推导或待验证假设 | 格式关系、候选方向 | 不能代替实际 API 的实现或数值结果 |

## Cast 与数据搬运

一个数已经由 dtype D 精确表示，再按 D 舍入是格式恒等关系；这不证明 `Cast<D,D>` API 是合法拷贝。目标重载可能不支持某个 RoundMode，断言或不产生数据。先核支持表/实现，真正搬运使用已定义的接口，不能把“省去 Cast”误写成“同 dtype Cast 等价于 copy”。

排序里提取出的 index 若已是最终 dtype，可以评估直接搬出；value 转换、别名和独立 buffer 仍按实际路径核算。使用独立输出 buffer 是一种保守实现选择，不是所有 Cast 的普遍限制。

## 别名与资源

是否允许 dst 与 src 重叠是接口事实；数学上能原地计算，不等于向量分段执行顺序安全。没有适用依据时按独立物理 buffer 预算；只有确认支持、同步及生命周期安全才采用别名。按[资源账本](resource-lifetime.md)唯一计数，不能从文档里的变量名推断复用。

## 近似函数与归约

不从知识卡引用通用 Rsqrt/Sqrt/Exp 的 ulp 或相对误差上限。精度取决于 API/公式、输入域、中间 dtype、舍入点和工具链。换成 Sqrt+Div 或增加精化同样要满足本任务原精度契约，并计入指令及临时量成本。

数学示例：精确算术中，若 `r0=(1+e)/sqrt(a)`，一步 `r1=r0*(1.5-0.5*a*r0*r0)` 的相对误差为 `-1.5e²-0.5e³`；实际浮点舍入和适用输入另评，不能据此宣称某平台已通过。

分段归约及累积顺序会改变舍入；使用更高精度不自动等于满足原 reference。对带索引的归约，还要核索引生成、整数到浮点转换的目标支持域和可精确表示范围；不把旧资料中“某 cast 不支持”写成所有编译器的结论。

## dtype 与比较器

- 一个 dtype 通过不能排除共享上游错误：其舍入、容差或执行路径可能不同。
- Add/Sub 等已有路由不覆盖 Mul/Div，只是路由缺项，不能推导原 dtype 直算足够精确。
- 多输出比较器若在第一个错误处返回，未执行的输出比较不能报告通过。
- 多点同时修改的差分不能把收益或修复归因于其中一个点；只在需要定位时按原流程缩小差分，不追加通用专项测试。

本文将原增强中 elewise、with-index、sort 的精度限定合并于此。精度公式或别名改变后，仍走原编译、正确性、性能流程；不改 reference、输入域或容差，不增加额外验收层。
