# 算子合同模板

根据已经核实的材料填写；未决项写明原因和影响范围。合同冻结前可以做源码分析和数据准备，不能把未知语义带入正式验收。

```text
run_id / contract_revision / mode:
算子名称、输入源码版本与入口:
计算语义、融合边界及允许的改写:
实现结构: 整算子 / C→V串行；选择依据及实现选型记录路径
实现来源与语言路线: 整体及各组件分别记录复用/适配/新生成、AscendC/TileLang
分阶段执行模式: 第0～4阶段Codex；第5～7阶段Codex＋Claude协作或Codex独立；第8阶段Codex复核
协调/执行/验收责任方、真实环境/cwd/会话身份:
阶段范围: full（默认完整开发）/ generation_only（用户指定）；演练按独立协议
允许连续推进的阶段、明确停点、当前看护授权/触发方式、接管规则:
输入/输出: 每个张量的 shape、dtype、stride/layout、逻辑与物理表示
可变状态、别名/in-place 关系、初始化/重置及未触碰区域:
动态轴、metadata 约束、合法值范围、空输入/尾块等边界:
正式 workload 路径、hash、完整 case_ids 与数量:
shape 来源: 源码推导 / profiling 观测 / 用户指定 / 明确假设
正确性 oracle 与版本、精度标准、NaN/Inf 与随机性协议:
原始性能基线 R: 源码/构建/加载路径与hash、完整被测调用
优化固定起点 G: 验证通过后追加其包ID、构建与加载库hash
计时: graph/kernel/端到端、包含哪些步骤、warmup、重复数、聚合规则
状态恢复/数据准备是否计入时间，以及基线与候选的相同条件:
运行环境: 设备型号、CANN/驱动/torch-npu等版本、容器与允许工作目录
资源使用规则、等待策略和污染样本处理:
生成目标: 默认 GM(R_us/G_us) >= 1.2
优化目标: 默认 GM(G_us/O_us) >= 1.5，G不得随冠军更换
预算: 最多5轮，每轮5候选；实际并发按资源和agent限制
生成修复/时间预算（另记）、进化停止条件及下游内部早停如何继续剩余预算:
若设时间预算: 有效执行/资源等待的计入规则、墙钟截止条件
不可变项: oracle、workload、caseIDs、精度、计时协议、固定分母
允许修改范围及人需决定的语义/结构性取舍:
交付路径、复现命令与最终验收人/协调者:
```

G 尚未生成时记录为待验证，不能预填 PASS。已有 AscendC 可以使用同一验证协议建立 G，generation 记为 SKIPPED_REUSED。若无 profiling 且按获准假设选 case，不得为这些 case 伪造生产出现频率。

合同发生实质变更时建立新修订，重新核对受影响的 workload、基线和候选证据；旧结果保留原合同身份。精度、全量覆盖或计时条件不满足时，不计算一个看似有效的总体达标结论。

## C/V 串行分支补充

外部合同先冻结，内部接口经实现检索和模板/tiling 选型后冻结，详见 [C→V 串行分支](cv-serial.md)。父合同引用 `IMPLEMENTATION_SELECTION.md` 与 `CV_BOUNDARY.md` 的修订/hash，以及父 case 到组件/chunk 的映射。

同时记录峰值缓冲和完整 case 的交接流量、预处理生命周期、实时适配计时归属、三层正确性协议、统一调用/评测入口。C/V 共享父任务的目标与预算；组件候选不得自行变更父 workload、数值语义或性能分母。G 冻结时包含整套 C/V 组合身份。
