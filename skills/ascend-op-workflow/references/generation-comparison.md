# 生成阶段对照

用户要求比较workflow生成与直接生成时，新建关联run，固定 `generation_only`，不启动进化。两路都从同一原始需求开始，不复用历史kernel、设计、冠军或另一臂结果；历史直接最优可额外计时，但不能混入本次生成工时。

两路使用同一真实 `ops-direct-invoke` 生成入口、模板及SDK资源版本、角色模型/effort配置、全量正确性、10例性能集、设备、随机种子和修复上限。直接臂从生成器进入，workflow臂额外执行shape/workload/合同/归档编排；这是本次比较的变量。保留原模板，只绑定任务变量；原生Codex的角色兼任、工具适配及独立审查情况如实记录。

生成时间上限独立于5小时优化预算，由任务冻结。修复计入累计上限，内部review重置计数不重置父预算。两臂使用相同父级累计修复规则。首次完整正确实现立即冻结；仅修复正确性，不在生成之后追加性能变异或进化搜索。性能不达目标也照实交付。

记录以下时间戳及原始事件：

- request_started_at：该臂实际开始接收任务；workflow专属准备计入该臂。
- generator_started_at：实际进入原生生成流水线（含原生环境/工程步骤）；另记首个角色的派发与接收时刻，避免混淆工具准备和模型执行。
- first_full_correct_at：当前源码/库通过完整正确性；立即冻结首个G。
- qualified_artifact_at：正式性能、独立核验与归档完成。
- 另列共享实验准备、模型/工具等待、CPU构建、NPU排队与运行、修复、验收时间。token缺失写unknown；包含所有角色和失败尝试。

先冻结两臂代码，再揭示彼此成绩。同卡串行测固定10例；正式结果从原始任务/stream记录核对，正确性集合不得缩到10例。报告各臂绝对耗时、GM与总耗时、逐例胜负、首次正确时间及合格产物时间。单次A/B仅说明该任务观测，不据此推断总体成功率或模型优劣。

角色排队、共同阶段屏障和CPU/NPU资源等待单列，既报告总墙钟也报告可核实的阶段执行时间。数据构造seed相同不代表模型采样可重复；模型temperature/解码seed无法观测时记unknown，不能声称所有随机性都受控。
