# 从 shape 到 tiling：复用原设计与验证

适用于新生成、缺失组件适配或主要数据通路变更。完整复用且证据有效时不重做设计。此文只补充原 DESIGN 的内容，不增加阶段、独立模板、审核角色或运行时门禁。

## 设计前读什么

先读原需求和已冻结的完整 workload，识别 shape、dtype、stride/布局、属性和输出语义。精简用例只供调试，不缩小支持域；观测到的 shape 不等于完整 API 支持范围。

按[知识路由](tiling-reading-routes.md)选择当前决策需要的本仓增量卡片及外部基础正文，实际读到相关内容后再形成方案。既有 Vector 卡片入口保持原位置；不把索引或资料文件名当作正文，不要求通读知识库。

先按算子家族确定语义与依赖，再组合适用的执行策略；公共规则统一引用资源、API/精度和运行期开销正文。家族与策略不是互斥分类，不为两维分别建立设计或验收记录。

## 在原 DESIGN 中做决定

将有意义的几何、布局或依赖条件归为同一设计范围，参数可由通用公式覆盖多个 shape。只由几何与平台能力分流，不按 case 编号或输入值记忆答案，也不要求增加分支数量。

| 应说明的内容 | 设计依据 |
|---|---|
| 分工 | 哪些输出独立、哪些位置存在归约或冲突依赖；并行轴及每核有效工作量 |
| 复用 | 一组输出共享哪些输入、参数或邻域；保留、重读或重算的代价 |
| 资源 | 按实际 dtype、对齐、队列深度、scratch 和同时存活关系计算峰值 buffer；平台预算有来源 |
| 成本 | 沿用原操作粒度成本表，比较实际搬运、串行依赖、同步、合并及准备开销 |
| 边界 | 最小尺寸、不整除尾段和布局限制；有效长度、分配容量、字节数和重复次数的区别 |

在原 DESIGN 已有的方案/卡片适用性表中写明命中的资料及版本/章节、适用条件、采用方式和关键取舍；只有一个合理方案时说明条件即可。资料与当前 SDK 不一致时以已核实的目标平台约束为准。

UB 放得下只证明可行，不能证明更快。核内分段也不自动增加核间任务。比较方案时使用同一 global/per-block/per-task 范围；不把源码调用数当硬件指令数，或把逻辑输入字节当实测 HBM 流量。

相关参数、成本或 API 支持未知时，在原设计记录中说明缺项及本轮处理；不猜造平台值，不为完成设计而默认增加探针、全量备选实现或测量。

## 参数必须落到实际代码

参数映射并入原 DESIGN 成本表或已有实现说明，不另建交接模板：

`适用 shape/布局 → 参数公式及单位 → host/launch 字段 → device 任务、循环与索引 → 有效尾段`

原设计走读检查公式覆盖和成本取舍；原实现检视核对真实代码符号、单位、取整方式、实际 buffer 分配及读写边界。若开发改变主要数据通路或操作粒度，沿已有 design_issue 更新设计并复审，不只修改文档迎合现状。

例如全局长度可整除不代表每核片段无尾块；应从每核有效长度检查搬入、计算和写回。增加 tile、核数或双缓冲时，应同时核对工作集和任务数变化，不能只改一个参数便宣称收益。

## 沿原验证流程给出结论

静态设计可行性、实际精度通过和性能改善分别报告。先按原合同编译和验证正确性，再对同一冻结候选完成原性能测量；默认用例集合、RNG、容差、预热/重复、预算及停止条件均不由本文改变。

已有有效同身份证据直接复用，修改后按原影响范围重验。逐 shape 退化沿原报告说明；无可靠改善保留原有效基线，不把资源合法或知识引用当作速度保证。

设计走读抽查所引用正文是否支持当前选择，开发者按同一引用读取并核实现位置。本文不增加自动阅读监控：真实读取记录可作参考，设计引用本身不能证明完整阅读。既有实验的继承和测量协议单独归档，不进入普通生成任务，也不事后补签历史阅读记录。
