# Shape 驱动的 tiling 设计与交接

本文是生成设计评审的按需参考，帮助把已确认的 workload 几何转成可实现、可复核的 tiling；它不是新的性能门槛，也不替代[生成设计评审](generation-design-review.md)、外部合同或 CANNBot 原有执行流程。使用[交接模板](shape-tiling-handoff.template.md)记录实际任务，未确认的信息标记 unknown。已冻结的历史 run 沿用其原合同和证据，不因本文追溯修改。

## 从 workload 到设计

1. 依据语义、实际 shape、dtype、布局/stride 和平台约束划分有意义的几何组，注明覆盖的 workload 及来源；区分观测、推导和假设。分流只能依赖通用几何和平台条件，不能按 case ID 或输入值记忆答案。
2. 对每组列出计算轴、连续访问轴、并行轴、边界及尾块。候选 tile 的适用域应明确维度范围、对齐和布局要求；尾块的读取、计算和写回须覆盖不整除及最小尺寸，不得越界或改变语义。
3. 按实际 dtype、缓冲区、对齐/padding、双缓冲和临时空间估算 UB 峰值，注明同时存活关系和可用预算的依据；库内部 workspace 未知时单列。估算核数、每核任务数和尾部负载，说明小规模并行不足或大规模分块的风险。
4. 从实际执行粒度估计重复输入读取、DMA 次数与粒度、同步/依赖往返、规约和标量 UB 访问；注明全局、每核或每任务的范围及公式。逻辑 tile 数不等于硬件指令数，源字节数不等于实测带宽流量。库内部未知不猜造。
5. 选择参数与备选时说明预期收益、额外开销和可证伪观察：例如增加 tile 后预计 DMA 次数下降，但 UB 压力或并行任务减少可能抵消收益；给出可区分这些原因的测量与反证条件。未授权探针时仅提出后续验证，不额外启动性能搜索。

结合实际算子识别成本反例：直方图类分桶若每个桶重复扫描输入，扫描量可能随桶数放大；插值类访问需考虑跨 tile 的邻域重复读取和 Gather 粒度；散射类操作需检查冲突、排序或分组代价，以及串行依赖和同步固定开销。它们是待核对的机制而非必然瓶颈，须结合规模、布局和实际实现给公式与测量计划。队列或缓冲的选型取决于数据依赖和平台约束，不预设某一种 API 必须使用或另一种非法；分支数量增加本身也不证明收益。

## Vector 算子：先判断依赖，再选 tile

“使用向量指令”不是切分依据。先找出哪些输出独立、哪些输入可复用、哪些位置必须维持更新顺序；再结合实际 shape、布局和 dtype 选取连续轴与核间分工。同一算子可含多种模式，不要求为每种模式生成一个分支。

| 主导模式 | 如何选取切分或复用单位 | 哪些开销或边界需要核算 |
| --- | --- | --- |
| 独立逐元素 | 输入输出同形且实际连续、无跨元素依赖时，可展平后给每核分连续片 | 以每核有效长度核尾段；类型提升会增加中间缓冲，小输入可能不足以摊薄分核成本 |
| 广播 | 按实际广播轴区分重复使用的值和连续输出；将可复用数据保留在片内 | 不为方便向量化而把广播输入整体物化；按 stride 和片长核算实际搬运与对齐 |
| 邻域读取或 Gather | 按一组输出共享的输入行或邻域切片，比较跨片重读与片内暂存 | 同时计算坐标/权重开销、非连续读取和边界处理；移到 host 的工作单列 |
| 归约或归一化 | 独立行充足时优先比较按行分工；归约轴放不下时核算分块累积 | 区分有效长度与填充长度，验证累积精度、中间结果合并、屏障和峰值缓冲 |
| 分桶或冲突更新 | 比较按输入切分后合并与按输出取得唯一写入权；先保证冲突语义 | 估算逐桶重扫、排序和合并成本；重复索引若要求顺序，不能为并行而重排 |

例如，逐桶循环中的上下界掩码若只取决于当前输入片，就可以比较“每桶计算”和“每片计算一次”。这不要求改变全局分块。是否值得采用，由原用例的正确性和逐 shape 计时检验。

## 从设计到实际实现

**尾块按核内有效长度核算。** 例如 96 个连续元素均分到 4 个核，每核只有 24 个。即使全局长度能被 32 整除，以 32 个元素为一组的核内操作仍有尾段。沿搬入、类型转换、排序或规约、写回逐步标明使用的是有效元素数、对齐容量、字节数还是重复次数；若指令只接收整组，说明余数如何被处理、填充值如何排除。分桶场景还可在同一输入上比对漏计的逐桶差值与各核尾段的直方图：逐桶相符支持“该尾段可能漏计”的假设。不同片段可能有相同直方图，漏计和重复计数也可能抵消；可结合逐核索引或逐阶段计数核实位置和原因。

交接必须能沿着“适用域 → tiling 参数及推导 → host 计算/序列化 → kernel 消费与索引 → 尾块处理”逐项追踪。说明 host 和 kernel 使用的字段、单位、整除/向上取整、数据类型及边界约束，并检查不同几何组的分流互斥和覆盖。把参数与代码的实际符号或位置绑定；若外部生成器尚未产出代码，先记预期映射，生成后再核对实际映射，偏差按现有 design_issue 流程处理。

设计记录纳入现有 DESIGN 和结构化评审证据，由独立审查者分别判断正确性与性能可行性；不新增独立自动门禁。`unknown`、估算或静态评审均不代表正确性或性能已通过。首次全量正确即按原流程冻结，测量、精度和后续优化仍由任务原合同决定。
