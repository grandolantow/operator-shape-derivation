# C→V 串行实现分支

用于将包含 Cube 与 Vector 阶段的完整算子拆成独立 kernel 串行执行，或恢复这类任务。本文补充主流程的实现选型、生成与优化交接，不另建一套目标或执行器。仅当进入此路线时读取。

## 1. 入口与拆分评估

先固定父算子的外部语义、完整 workload、独立正确性 oracle、基线 R 和计时协议。列出 C/V 边界草案，再检查可复用实现；内部 layout 尚不因草案而锁死。用户已指定路线时直接落实其授权；尚未选定时，给出支持范围、性能与工程取舍，在已有授权内选择。

- 估算中间张量的逻辑/物理大小、峰值缓冲、完整父 case 的累计 GM 读写和额外 launch/适配成本。分 chunk 降低峰值，不自动降低总交接流量；逻辑 GM 流量也不直接等于实际 HBM 流量。
- 可采用 `C0→V0→C1→V1`，但必须覆盖父 case 的完整范围，定义跨 chunk 的归约、TopK 合并和状态依赖。跨 kernel 并发、片上交接或重新融合属于另行评估的实现变更，不是串行首版的隐含条件。
- 基线功能必须可比。某基线缺少 candidate 等输出时，完整工程预算对照与公共功能性能对照分开；不能删掉正式功能或 case 来形成同功能加速结论。

## 2. 生成前检索 C/V 成熟实现

分别检查原算子实现、项目已验证版本、目标 CANN/SoC 的库和模板及相近算子。按真实语义、数据路径和适配成本排序，不只按模板名称。复用应尽可能保留有效的调度、搬运、缓冲和同步流水；仅移植 Mmad/向量指令片段不等于复用完整实现。

将 C、V 候选和后续筛选写入同一份 `IMPLEMENTATION_SELECTION.md`，至少包含：

| 字段 | 内容 |
|---|---|
| 来源 | 源码/模板入口、revision/hash、目标 SoC 与 SDK |
| 支持范围 | 运算、dtype/累加/舍入、量化 scale、状态、mask、TopK 等适用条件 |
| 数据接口 | 逻辑与物理 shape、格式、stride、分页/分组、输入输出所在存储层级 |
| 适配成本 | gather、cast、repack、布局或 GM 读写改造；静态预处理与每次调用的边界 |
| 完整流水 | 可复用的任务调度、搬运/计算重叠、buffer 与同步；需要修改的部分 |
| 验证状态 | 源码适用 / 编译通过 / 子集正确 / 全量正确 / 性能有效，附证据位置 |
| 选择结论 | 选中、保留回退或排除的原因；未验证假设 |

C、V 可以选不同来源。存在适配实现时优先复用；缺失部分才交给生成技能开发。静态权重预打包需规定更新、失效和 graph 指针生命周期；实时数据转换必须计入完整路径。张量 dtype 名称、`NZ` 标记或逻辑 shape 不能证明物理布局兼容。

## 3. 结合 workload 筛选模板与 tiling

在生成前的设计/最小适配阶段完成有限筛选，不以长期重写代替选型。保留通用正确回退，在父任务记录筛选的计算/时间预算；这不是额外开启一套 5×5 优化搜索。

1. 从正式 case 提取 M/N/K、请求/head/组数、有效长度、尾块、布局/stride、量化和分页等结构；区分观测频率与人为覆盖，重复 shape 不自动代表生产权重。
2. 先核对目标平台与 API 适用性，再检查核间任务数、每核工作量、L1/L0/UB 容量、buffer 份数和尾块条件。记录预计数据复用/搬运量；不凭“更大 tile”“更多 K 驻留”“已用双缓冲”宣称更快。
3. 对少量合法候选测代表形状和分档边界，含非整除与大工作量；V 同时检查访问顺序、归约/选择器 scratch、状态和合并开销。尚无可执行适配时标为暂选，完成最小适配和验证后回填，避免选型与生成互相等待。无设备时记 `WAITING_RESOURCES`，继续源码适配、CPU 构造等允许的独立工作；设备正确性和性能保持待测，不启动 NPU 评测/搜索，也不把 production 自动改成 rehearsal。
4. 用 shape、布局、容量与任务结构制定少数分档规则。避免按 case ID 或几个精确 T 点拟合；固定 shape 特化需有明确支持域。用未参与筛选的合法邻近 shape 检查泛化，并在正式完整 workload 上复验。
5. 分别记录开发子集、独立覆盖集和正式 workload 的结果；额外覆盖不修改父 case 数量/权重。检查总体收益、最差退化及重复测量稳定性。选择相同 kernel/tiling 时，微小计时变化不算新优化；无可靠收益保留旧版本，归档失败方向。

优先调用目标环境已有的 tiling、模板、profiling 专业技能；按真实入口和版本读取，不在本文复制硬件常量、历史 tile 或特定任务容差。PMU 活跃比例用于定位线索，结合 trace/等待及同条件 A/B 决定优化；不同计时层级不混合计算收益。

## 4. 内部合同与组件数据

实现选型后冻结 `CV_BOUNDARY.md`，由父协调者统一版本化。最小内容为：

```text
parent_task_id / contract_revision / boundary_revision:
C/V 数学分工与运算顺序:
中间张量: 逻辑/物理 shape、dtype、累加与舍入、layout、stride、对齐
有效区/尾块/padding、mask、量化 scale、符号与数值范围:
buffer 所有权/生命周期、写读顺序、同步、可变状态与重置:
chunk 覆盖、顺序、尾块、跨 chunk 合并及峰值内存预算:
静态预处理/实时适配的责任方、缓存失效与计时归属:
C reference、V reference 及独立输入构造方法:
父 case → 组件 case/chunk 映射、seed/metadata/完整工作量:
组件和整体验证命令、允许修改项及接口变更流程:
```

由父 workload 派生 C、V definition/workload，保留原 case ID、完整 shape、seed、metadata 和来源；chunk 使用子 ID 并映射回父 case。CPU 小用例和开发子集另列，不替代正式全量。内部 ABI 改变时重新核对相关组件数据包与 loader；C/V 各自不能单边改变边界。

## 5. 适配生成与组合验收

通过现有生成入口执行所选实现路线，交接父合同、边界、选型记录、完整 case 映射、源码定位、允许改动范围与验证命令。明确哪些组件直接复用、哪些适配、哪些新生成，以及直接 AscendC 或 TileLang 路线；不要因为入口名含 TileLang 就重写成熟 AscendC 组件。缺少对应工具或接口时记录实际缺口。

先形成可调用的 C0/V0 完整串行工程，再根据测量迭代。必须分别取得：

- **C 独立正确性**：对独立 reference 检查中间输出及其精度/有效区。
- **V 独立正确性**：正式测试输入来自独立 C reference 或已核实 fixture，不只用候选 C 给 V 生成 golden；覆盖合同要求的状态、mask、尾块与选择语义。
- **C→V 全量正确性**：真实 C 输出进入真实 V，对完整 oracle 检查所有外部输出、可变状态和未触碰区域，并按合同验证图重放。

组件正确不转移为组合正确；成熟基线也不替代独立 oracle。按父任务当前阶段处理新组合：

- **G 尚未建立**：新组装或适配的 C→V 走父任务生成验收；只有完整已有工程验证复用时父任务才记 `SKIPPED_REUSED`。首个 G 冻结为组合包：**C 版本 + V 版本 + 边界版本 + tiling/路由 + chunk/适配逻辑 + 统一调用与评测入口 + 构建/加载身份**。父任务生成目标默认 R/G≥1.2，以完整路径计时；全量正确且正式性能有效但目标未达时，如实交接已授权优化。
- **G 已冻结，优化中转入本分支**：新串行组合是相对原 G 的 O 候选；即使需要调用生成技能适配组件，父阶段仍是优化。执行同样的三层正确性与完整计时，消耗剩余优化预算；不重新做 R/G 生成目标判定，不把新组合重命名为 G。原 G 可以是融合实现，冻结身份与分母保持不变。

## 6. 交给 ops-perf-evolution

交接完整组合工程和 runner，附 C、V、适配阶段诊断数据。若下游默认只测单 kernel，先完成全路径评测适配并核验实际任务覆盖；没有可用适配时记录缺口，不能把组件分数冒充父任务闭环。

候选可以是 `C-only`、`V-only` 或 `joint`：前两者固定另一组件和边界；joint 改边界时同步更新双方与 runner，并重跑受影响的独立测试及完整组合验证。每个候选用完整组合身份登记，防止把两个不同父版本的组件成绩拼接。

- 默认 **5 轮×每轮5候选是父任务总上限**，C/V 搜索共享，实际并发按授权资源。冻结 G/O 默认1.5×，用户目标优先；组件改善只作诊断，不把1.2/1.5目标逐个分配给 C、V。
- 用首个正确 C0/V0 的耗时占比、适配开销和完整目标形成组件微秒预算；预算是调优方向，不保证每个组件具有相同加速空间。
- 按同一父 case、输入、设备和计时协议报告 R/G/O 整体耗时，另列可独立实测的 C、V、辅助任务耗时。融合基线无独立 C/V 测量时标未测，不能拆估成实测值。
- Graph Event、设备任务时长之和、端到端与模拟器周期分别记录。串行图按冻结口径计入全部 chunk 及必需的 gather、layout、metadata、清零和输出处理；图内/外的状态重置按合同一致处理。完整计时须来自实际运行，不能靠单 chunk 乘次数冒充。

## 7. 归档、恢复与最终交付

使用[归档协议](protocol.md)中的一个父状态入口。最少增加两份设计材料：`IMPLEMENTATION_SELECTION.md` 与 `CV_BOUNDARY.md`；组件 case 映射归入 benchmark manifest，无需为每个步骤再建同义文档。

生成与优化交接单列出：父合同/边界修订、C/V/组合包身份、选型及已否决方向、完整 case 映射、三层正确性、统一 runner、计时协议、固定分母、已用和剩余预算、真实下一步及证据路径。子任务完成不能直接关闭父任务。

中途转入串行路线时保留 R、有效数据/证据和已用预算，版本化实现设计；已冻结 G 不随路线改变。接口或支持域变化使相应验证失效，旧结果仍保留旧身份。需要改变验收基线/语义/预算时沿用主流程的人参与规则。CLI 冻结身份变更的归档方式见 [CLI 限制](../scripts/CLI.md)。

最终交付一个可复现的完整算子入口、C/V 源码与构建、依赖和 case/状态合同；实验过程、失败候选与原始数据留在实验归档中。分别报告组件、完整精度、性能有效性、生成/优化目标；局部 PASS、CPU 包装检查或旧库测量不能替代最终交付版本的 NPU 证据。
