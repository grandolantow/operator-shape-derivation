# 连续推进与停止判定

用于任务启动、G 冻结、进化提前返回或恢复时判断下一步。这里约束执行 agent；安装 skill、运行归档 CLI 不会自行创建执行进程或定时服务。

## 任务终点

在父合同或已有任务状态中用自然语言记录范围，也可用 `stage_scope`：

| 范围 | 停止点 |
|---|---|
| `auto`，新任务默认 | 直接生成/复用首版 → 轻量验收；达标交付 G，未达标进入优化 O |
| `full`，用户明确要求优化 | 生成/复用 G → 实际进化 O → 最终验收与交付 |
| `generation_only`，用户明确只要求生成 | G 验收、冻结及优化交接；进化标 NOT_RUN |
| `rehearsal` / 执行启动核验 | 按各自协议的限定停点，不能视为正式完整交付 |

新建归档默认 `--stage-scope auto`；`full` 仅覆盖是否必须优化，不放宽新正式任务的固定10例与逐轮复盘要求。`generation_only` 固定仅生成范围，CLI 会拒绝优化交接。旧run未记录stage_scope时继续沿用full语义，不迁移冻结身份。沿用当前授权范围；用户仅问问题、要求整理文档或已暂停任务时，不因此启动旧任务。

## 首版轻量验收与分流

默认直接生成首版，或验证已知可复用实现。必要的语义、精度、资源及同步审查仍执行；首版前不强制展开多路线性能搜索，也不预先限定kernel数量、C/V拆分、融合边界或中间GM布局。实现结构可随证据修正，外部算子合同保持一致。

轻量指先完成一次验收决策，再决定是否搜索；不是减少正确性覆盖、性能重复次数或证据核查。

1. 首个全量正确实现冻结为G。核对正式workload、固定10例（超大最多3例）、计时协议、有效样本及源码/构建/实际加载库身份。没有合格G先修复。
2. 完成同协议R/G测量，通过 `prepare generation`、`result generation` 归档，调用 `decision --run RUN --candidate G`。已有完整AscendC可记实现生成SKIPPED_REUSED，但auto路线也必须归档实测R/G验收；仅有validated精度证据不足以决定性能路线。
3. auto下，全量正确且达到合同生成目标时交付G，优化记NOT_NEEDED；性能有效但目标未达时记录GENERATION_TARGET_UNMET并进入已授权优化。缺失、无效、rehearsal或相互矛盾的测量先补验/核查，不能推断达标或挑选方便的结果。
4. 默认CLI生成目标为GM(R/G)≥1.2，优化目标为固定GM(G/O)≥1.5，两者不可混用。用户指定的目标在init冻结；局部退化、端到端目标等额外验收条件必须事前写入合同并由协调者核查，CLI的GM路由不证明这些条件通过。generation_only即使性能未达也不进入优化，交付时明确TARGET_UNMET。

## 从 G 进入进化

仅auto的有效性能未达标，或用户明确指定full时进入。固定G后，后续冠军只作O，不能替换分母。

1. 在原任务中读取实际 `ops-perf-evolution` 入口并调用适用agent/命令，传入完整工程、冻结G、正式verifier和剩余父预算。未另约定时沿用有效执行最多5小时、最多5轮×5候选；用户指定预算/轮数优先，C/V共用父预算。归档CLI不自动计时或派发。
2. 先基于慢例提出可证伪的瓶颈假设，再设计候选；控制变量，结构改动与参数调整都允许。持续无收益时按合同早停条件停止，不能靠机械排列组合消耗预算。每轮结束完成全部结果的根因/方向分析，并通过round-check后再派下一轮。
3. 归档接收、实际调用、首个候选实现/构建/评测的证据。HANDOFF、prepare、空候选目录和agent正常返回分别只证明对应动作，不能证明进化已运行。换进程前核实原执行者无重叠计算/写入。

执行端通过合同 verifier 后可继续已授权优化，Codex 的独立复核保留为父任务验收，不要求每个阶段等用户批准。若复核发现 G 或计时无效，保留原结果，修复并重新建立相关证据，不能沿用失效成绩。

## 进化返回后的判定

| 事实 | 下一步 |
|---|---|
| 正式全量精度及固定 G/O 目标均通过 | 固定最佳 O，复核后交付 |
| 内部 score 达标，但正式 G/O 未达或尚未测 | 先做正式验收；未达且预算仍有余量时继续原搜索 |
| 某候选精度失败/超时/取消 | 记录终态并推进其他合法候选，不等其性能文件 |
| 一轮结束、未达标、预算仍有余量 | 先完成所有候选的慢例/失败分析、归档 round-review，再通过 round-check 进入下一轮 |
| 达到合同搜索/时间上限，或命中预先约定的早停条件 | 交付已有最佳正确版本及 TARGET_UNMET；没有改进则保留 G，明确未获得更优 O |
| 外部故障或资源条件暂不满足 | 保留可恢复状态和未完成项；故障不等于预算耗尽或验收完成 |
| 用户暂停 | 保存检查点，核实本任务进程停止，按范围暂停看护；修好环境不会自动撤销暂停 |

恢复沿用父任务、固定 G 和累计预算。新建目录、重新启动 agent 或迁移环境都不产生新的5×5预算。生成阶段的修复/时间上限另记，不把优化的5×5借作无限生成重试。

## 执行持续性

长时生成/搜索必须明确谁在等待子 agent、何时写父任务终态。非交互 CLI 返回前核实子任务是否完成，或已有获准的持久执行者负责接续；不能把“已派后台 agent”视为交付。具体等待选项以实测 CLI 版本为准，不把历史私有环境变量硬编码为通用要求。

父任务关闭前核对：阶段范围已完成或有真实停止原因、每候选状态已对账、本任务剩余进程已核实、源码/库/结果可关联、报告明确未测项与未达目标。停止看护与停止执行分别记录。
