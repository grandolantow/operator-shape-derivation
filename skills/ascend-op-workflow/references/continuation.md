# 连续推进与停止判定

用于任务启动、G 冻结、进化提前返回或恢复时判断下一步。这里约束执行 agent；安装 skill、运行归档 CLI 不会自行创建执行进程或定时服务。

## 任务终点

在父合同或已有任务状态中用自然语言记录范围，也可用 `stage_scope`：

| 范围 | 停止点 |
|---|---|
| `full`，完整开发的默认值 | 生成/复用 G → 实际进化 O → 最终验收与交付 |
| `generation_only`，用户明确只要求生成 | G 验收、冻结及优化交接；进化标 NOT_RUN |
| `rehearsal` / 执行启动核验 | 按各自协议的限定停点，不能视为正式完整交付 |

这些是任务记录字段，不是 `workflow.py` 已有的命令参数。沿用当前授权范围；用户仅问问题、要求整理文档或已暂停任务时，不因此启动旧任务。

## 从 G 进入进化

1. 核对 G 的完整正确性、正式 workload、计时协议和有效样本，以及源码、构建和实际加载库身份。没有合格 G 先修复，不交付虚假的优化起点。
2. 记录 R/G 是否达到生成目标。`GENERATION_TARGET_UNMET` 不阻断 `full` 任务进入进化；已验证已有实现的首次生成记 SKIPPED_REUSED。固定 G 后，后续冠军只作 O，不能替换分母。
3. 在原任务中读取实际 `ops-perf-evolution` 入口并调用其适用 agent/命令，传入完整工程、冻结 G、正式 verifier 和剩余父预算。默认最多5轮×5候选、固定 G/O≥1.5；C/V 共用这份预算。
4. 归档接收、实际调用、首个候选实现/构建/评测的证据。HANDOFF、prepare、空候选目录和 agent 正常返回分别只证明对应动作，不能证明进化已运行。若需要换进程，核实原执行者无重叠计算/写入后再交接。

执行端通过合同 verifier 后可继续已授权优化，Codex 的独立复核保留为父任务验收，不要求每个阶段等用户批准。若复核发现 G 或计时无效，保留原结果，修复并重新建立相关证据，不能沿用失效成绩。

## 进化返回后的判定

| 事实 | 下一步 |
|---|---|
| 正式全量精度及固定 G/O 目标均通过 | 固定最佳 O，复核后交付 |
| 内部 score 达标，但正式 G/O 未达或尚未测 | 先做正式验收；未达且预算仍有余量时继续原搜索 |
| 某候选精度失败/超时/取消 | 记录终态并推进其他合法候选，不等其性能文件 |
| 一轮结束、未达标、预算仍有余量 | 进入下一轮，不把一轮报告当父任务收尾 |
| 达到合同搜索/时间上限，或命中预先约定的早停条件 | 交付已有最佳正确版本及 TARGET_UNMET；没有改进则保留 G，明确未获得更优 O |
| 外部故障或资源条件暂不满足 | 保留可恢复状态和未完成项；故障不等于预算耗尽或验收完成 |
| 用户暂停 | 保存检查点，核实本任务进程停止，按范围暂停看护；修好环境不会自动撤销暂停 |

恢复沿用父任务、固定 G 和累计预算。新建目录、重新启动 agent 或迁移环境都不产生新的5×5预算。生成阶段的修复/时间上限另记，不把优化的5×5借作无限生成重试。

## 执行持续性

长时生成/搜索必须明确谁在等待子 agent、何时写父任务终态。非交互 CLI 返回前核实子任务是否完成，或已有获准的持久执行者负责接续；不能把“已派后台 agent”视为交付。具体等待选项以实测 CLI 版本为准，不把历史私有环境变量硬编码为通用要求。

父任务关闭前核对：阶段范围已完成或有真实停止原因、每候选状态已对账、本任务剩余进程已核实、源码/库/结果可关联、报告明确未测项与未达目标。停止看护与停止执行分别记录。
