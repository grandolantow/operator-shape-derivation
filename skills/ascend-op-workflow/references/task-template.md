# 开始任务的最小输入

已有对话给定的条件直接填写，不把本模板当必须交给用户填的问卷。

```text
使用 ascend-op-workflow 完成算子开发。
输入算子：<实际文件/函数或工程路径>
输入类型：AscendC / Triton / torch组合
配置/shape/profiling：<已提供材料；无则如实记录>
目标环境：<已确认alias、容器和工作目录>
benchmark与CANNBot：<实际路径，尚未核实则先发现>
执行模式：production（真实开发） / rehearsal（仅验证接线）
执行分工：第0～4阶段由Codex负责；第5～7阶段选择<Codex＋Claude协作 / Codex独立完成>；第8阶段Codex复核交付
已有执行会话：<环境、任务cwd、tmux/pane或session；无则按授权准备>
阶段范围：auto（默认：直接生成/复用→轻量验收→达标交付、未达标优化）；full为用户明确要求进化；generation_only为仅生成
阶段停点与看护：<auto记录验收decision与交付/优化分支；full不在G交接处停止，未授权则不建定时任务>
原始基线R：<完整被测调用>
计量方式：<与实际业务一致的模式及边界>
已有可复用AscendC：<路径或无>
实现结构：<默认不预设；记录已有依据或用户约束，允许随证据修订>
C/V已有实现线索：<原算子或项目版本；不清楚时由Agent检索>
默认生成目标：R/G >= 1.2
默认优化目标：固定G/O >= 1.5
默认优化预算：有效执行5小时、最多5轮，每轮5候选；按设备和Agent限制分批
性能用例：预先冻结恰好10例，按算量/逻辑中间规模分类，超大例不超过3例；正确性保留原始全量
逐轮诊断：每轮结束先分析各候选慢例及下一步区分实验，再派下一轮
生成路线：plugins-official/ops-direct-invoke 原生 AscendC 分阶段生成
实现前设计门禁：按 generation-design-review.md 核查路线、操作粒度成本与独立性能可行性；设计者回应风险，独立复核后运行 design_check.py；回执只表示静态实现放行
首版冻结：首个全量正确版本立即冻结G；设计检查不代替固定10例实测及generation result/decision，不增加冻结前性能搜索
精度/状态/支持域：<从接口与既有标准确定>
归档目录：<独立run>
资源规则：<本次授权>
```

未提供profiling时，不凭空创造观测分布。正式计时口径未知时先完成源码和shape等独立工作，提出计量建议后再采样。已存在正确实现可跳过生成，但仍需验证其支持域和基线。

新任务在 `init` 传入 `--optimization-seconds 18000 --require-round-reviews`，仅生成任务另传 `--stage-scope generation_only`。同一 case manifest 同时承载完整正确性 IDs 和固定10例性能 IDs；不要改写历史 run 的冻结身份。仅生成对比另用 [对照协议](generation-comparison.md)记录独立时间上限。

新生成在派发实现前读取[生成设计评审](generation-design-review.md)，将 DESIGN、结构化评审、绑定的合同/workload/环境依据与 `design_check.py` 回执交给开发者。主协调者核对真实独立角色及原文；open问题退回设计，已回应并独立接受的风险保留原high_risk/unknown标签。数学相同但操作粒度明显变细也需回报design_issue。验证过且路线未变的完整复用工程沿用有效证据，不要求对旧run补字段。

按[连续推进规则](continuation.md)核对实测验收：auto达标交付G、未达标进入进化；显式full在合格G冻结后继续已授权进化，无需再次确认。此模板不能覆盖用户已经明确的仅生成、暂停或其他停点。

双端协作时读取[执行模式与监工协议](execution-modes.md)，把任务下发到已核实的 Claude 会话并确认接收/实际执行。这里只记录当前授权和已存在的安排，不把模板当申请所有权限或周期监控的问卷。

选择串行分支时可补充以下要求，具体规则见 [C→V 串行分支](cv-serial.md)：

```text
按 C→V 串行路线实现，生成前分别寻找成熟 C/V 实现，结合完整 workload
筛选模板、tiling 和适配成本，再冻结内部接口。先复用，缺失部分再生成。
保留父 case 和完整工作量，分别验证 C、V 与完整组合。
将完整组合工程、统一 runner、选型/失败记录和固定 G 交给优化技能；
5轮×5候选为父任务总预算，最终按完整路径验收。
```

## 每次对用户的阶段摘要

只呈现当前有变化的事项：目标和边界、已核实证据、待判决点、当前阶段真实状态、下一步。不能以「已生成handoff」替代「接收者已读取并开始准备」，也不能把「完成准备」说成「算子已生成」。

## 最终结论字段

分别报告 benchmark加载、生成准备、真实生成、全量正确性、正式性能、优化准备、真实搜索、最终验收。演练只允许前述相应准备项通过，真实生成与性能都标NOT_RUN。
