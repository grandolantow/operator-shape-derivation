# API 精度与语义注记

适用于 Cast、近似数学、归约累加、别名和编译器能力等假设。以下保留原知识中的机制、反例与版本位置；历史源码观察没有在本次重新审计，不等于当前目标 SDK 已核实。物理口径见[资源生命周期](resource-lifetime.md)。

## 证据与适用域

| 证据 | 含义与用法 |
|---|---|
| 目标版本文档/源码 | 指出平台、版本、重载、dtype、RoundMode 和具体位置后，可支撑该范围的设计；版本变化需重新核对 |
| 受控观察 | 只能说明记录覆盖的输入、实现与环境，不自动推广 |
| 假设 | 尚无适用证据的解释，留为待核证项，不能写成已确认的 API 事实 |

每条判断分别标注，不能以整份资料的可信度替代具体结论的支持域。原来源的历史审计位置保留在下文；本卡不携带设备实验轮次、结果表或性能数字。

## 1. 同 dtype Cast 不等于拷贝

格式数学上，已在 dtype D 中表示的值再舍入到 D 可以是恒等变换；Cast API 是否执行拷贝、有何别名与对齐限制，是另一件事。

原来源记录的反例限定为 **dav_c220 / CANN 9.2.0 / float→float / CAST_NONE**：

- `basic_api/dav_c220/kernel_operator_vec_vconv_impl.h` 的 float→float 重载起于约 508 行，`CAST_NONE` 分支只有 `DEBUG_ASSERT(false)` 后 break，没有拷贝指令；`CAST_ODD` 也不支持。
- 同一重载的 RINT/FLOOR/CEIL/ROUND/TRUNC 分别对应 `vconv_f322f32*`；`CAST_NONE = 0` 见 `kernel_utils_mode.h:95`。
- 这是原快照对特定重载的源码观察，不是所有同 dtype Cast 都无效的结论。目标版本应重新查看对应实现，不能以“数学恒等”或“编译器优化掉了”解释未知行为。

需要拷贝时使用该目标版本行为已定义的拷贝方式。能否省去转换 buffer，要由实际消费者接受的 dtype、地址与生命周期共同决定。

## 2. Rsqrt 等近似数学没有通用精度数字

精度结论需绑定具体 API/公式、中间 dtype、舍入点、平台、编译器及优化级别。CPU 的数值演示不能代验 device 指令精度，最终输出反推的误差也不能当成单指令硬件规格。

原来源记录：dav_c220 的 Level2 `RsqrtImpl`（`kernel_operator_vec_unary_impl.h` 约 353–393 行）直接下发 `vrsqrt`，wrapper 内未做精化，所述重载为 half/float。同样仅是该版本历史源码观察。

保留一个可核算的数值关系：对 `a>0`，若 `r0=(1+e)/sqrt(a)`，精确算术下的一步 Newton 精化

```text
r1 = r0 * (1.5 - 0.5 * a * r0 * r0)
relative_error(r1) = -1.5 * e² - 0.5 * e³
```

误差主项为负、量级为 e²；实际浮点运算还会引入中间舍入，极值、下溢/上溢及 API 支持域需另查。它是候选公式，不能因此机械替换全部 Rsqrt，或宣称满足任意算子的容差。

## 3. in-place / 别名能力逐重载核对

- 保守账本按独立输入、输出物理 buffer 计算；只有目标 API 允许且依赖、生命周期成立时才按同槽复用。
- API 接受某 src/dst 完全重合，不等于允许任意部分重叠；dtype、形状、向量段内读改写顺序也可能改变结果。
- Cast 的独立输出 buffer 是一种保守实现选择，不是通用定律；省略 Cast 和执行同 dtype Cast 也不等价。
- 数值无差异的有限观察仅覆盖其输入和环境，不能单独证明全部别名模式安全。

对排序，输入 fp32 时是否直接复用为 value buffer、Extract 后是否需要独立的 Cast 输出，都按这些条件决定，不能把参考工程的分配方式提升为 API 禁令。排序的工作区和有效长度另见[归并边界](../sort/merge-boundaries.md)。

## 4. 一个 dtype 通过不能排除共享上游原因

不同 dtype 可能使用不同中间舍入和容差。较宽容差下通过，可以掩盖共享的归约误差、近似误差、同步或边界错误；不能由 bf16 通过推出 fp16 失败一定在 Cast。

捆绑改动后的通过不能归因于某一个改动。结果未变只否定该改动足以解释差异，不能排除未覆盖输入中的问题；根因解释仍须区分观察与假设。

比较器也可能短路：若 output[0] 失败后不再比较 output[1]，不能声称 output[1] 已通过。分量结论必须对应实际执行并保存的比较结果，期望值和容差沿用原规格。

## 5. 编译器能力与索引表示

原归约索引资料中“aicore 不支持 `static_cast<float>(uint32_t)`”没有绑定编译器版本，应作为待核实的历史说法，不能用于否决当前工具链。

以 float 累加器逐次加 1 生成索引也有表示域：float32 只保证不超过 2²⁴ 的连续整数精确表示。超过该范围须核实索引生成与输出类型，不能当作任意 uint32 索引的替代。基础归约索引算法从固定 CANNBot 的 `references/reduction/with-index.md` 阅读，编译器和表示域判断以本节为准。

## 6. 症状、路由缺口与事实分别处理

| 原资料中的表述 | 使用边界 |
|---|---|
| DataCopy 不支持非对齐 | 先核平台、具体搬运 API 和粒度，不作所有版本的无条件属性 |
| Mul/Div 暂未覆盖，走原 dtype 路线 | 是路由缺口，不证明直算精度足够；需符合当前中间舍入合同 |
| FP16 精度差来自中间精度不足 | 仅为候选原因；舍入、别名、同步和越界也可能产生同一症状 |
| fp32 输入无需 Cast | 要求消费者与 buffer 生命周期允许，不能推导同 dtype Cast 等价于 copy |

相关设计、修复与验收沿用[生成设计评审](../../generation-design-review.md)，不另建测试流程。
