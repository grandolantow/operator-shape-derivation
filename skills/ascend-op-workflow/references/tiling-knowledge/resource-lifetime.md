# 资源与边界：按物理分配核算

用于原 DESIGN 成本表及 host/kernel 映射核对。UB、核数、对齐、队列/事件容量与 API scratch 取自目标平台、SDK 或已核实查询，不能沿用资料中的示例常数。

## Buffer 与生命周期

按 byte 列出真实物理分配：输入/输出 dtype、FP32 中间量、参数常驻、padding、队列槽数、独立临时量和库 scratch。逻辑 tensor 的别名不是新物理分配；队列深度为 2 已包含两槽，不能再加一次“双缓冲”。

```text
U_required = reserve + Σ(align_up(slot_bytes, alignment) × physical_copies)
U_required <= U_total
```

逐项分配及对齐以目标实现为准。reserve 只扣一次；若使用已扣预留的 U_available，则只比较物理分配之和。库内部未知开销单列 unknown。

- 最后一次逻辑使用不等于物理释放。独立 InitBuffer 的占用不能仅因 FreeTensor 就从账本扣除；阶段取 max 须有同槽合法复用或已核实的重初始化支持。
- 同槽复用需核对依赖、事件与最后一次读写完成；分阶段 Reset 先核实同步及目标 SDK 语义。写到 GM 的中间量在消费完成前保留其生命周期。
- 双缓冲增加容量需求，是否能重叠还取决于循环和交接。比较单双缓冲时重算 tile、每核迭代与有效工作核数。

## 参数、位宽与尾段

- 元素数、byte、对齐容量和 repeat/blockCount 等 API 字段分别标单位；乘法与向上取整先在足够宽的类型中运算，并检查结果与目标字段可表示范围。
- Host 可表示不代表 Device 的 DMA 字段可表示。遇到字段上限时按 API 支持方式分块或排除该分支，不能靠强制转换截断。
- 按每核有效长度处理搬入、计算和写回。96 个元素分到 4 核后每核为 24；全局能被 32 整除，不能证明核内按 32 元素分组的操作没有尾段。
- 分配容量与有效长度分别传递；对齐填充不能参与有效统计或越过输出范围。核间余数、核内尾块和最小合法尺寸分别核对。

实现位置与设计不一致时沿原 design_issue 处理；容量合法不证明精度或性能通过。来源与适用边界见 [SOURCES.md](SOURCES.md)。
