# 从语义和工作集选择 Vector tile

先确认布局、被归约的轴及不能拆开的语义组，再选下表的候选。M 是独立行数，N 是行宽，P 是现场可用 Vector 核数；B_M、B_N 是 tile 行列数，Q 是可独立分配的任务数。示例不是切换阈值；原指南的推荐分是工程判断，不是性能排名。此表不用于 MatMul 的 Cube 切分。

| 模板 | 核间/核内分工 | 适用条件与示例 | 主要反例 |
|---|---|---|---|
| 连续一维切分（Flatten） | 核间分连续区间，核内按固定长度分块 | 内存连续；各输出元素独立；总元素数足以形成多个有效搬运块。Add/SiLU：`[4096,4096]`；大向量 Cast：`[16777216]` | 归约、广播、stride 或配对关系不能被直接忽略 |
| 按行分核、归约轴全载（AR Full-load） | 核间分行；核内保留完整 `N`，完成归约和输出 | `[M,N]` 沿 `N` 归约；`U_live(1,N) ≤ U_avail`；`M` 足以提供并行度。RMSNorm：`[2048,4096]`；Softmax：`[4096,1024]` | 示例仍需核算 UB；`M` 很小时容易核数不足 |
| 多行合并（Merge-row） | 一个 tile 放入 `[B_M,N]`，每行分别归约 | `N` 较小、`M` 较大；`U_live(B_M,N) ≤ U_avail`；合并后仍有足够任务。短 Softmax：`[8192,128]`；短行归一化：`[4096,256]` | 合并过大会令 `Q=ceil(M/B_M)` 过小；必须保持各行统计独立 |
| 二维切分（Tile-MN） | 切成 `[B_M,B_N]`，将独立 tile 分给各核 | 存在广播、成对输入或行边界；列 tile 能独立输出或包含完整语义组。SwiGLU 输入 `[1024,2,11008]`、输出 `[1024,11008]`；广播乘 `[2048,4096] × [4096]` | 如果 `N` 是全行归约轴，列 tile 不能独立完成归一化 |
| 核内分段归约（Split-R / Recompute） | 核间仍按行分；同一核遍历多个列块，积累统计量，再分块输出 | `U_live(1,N) > U_avail`；`M` 仍有足够独立行；或融合后工作集过大。大词表 Softmax：`[128,131072]`；超长行 RMSNorm：`[256,32768]` | 输入可能多遍读取或重算；不会增加单行的核间并行度 |
| 非尾轴归约（RA / ARA） | 沿连续 `A₀` 切片并行，每个任务沿 `R` 归约 | `[A₁,R,A₀]` 中 `A₀>1`；保留连续内层维有利于搬运。`[32,1024,128]` 沿中间的 `1024` 维做 Softmax | `R×B_A` 的工作集需适配 UB；`R` 太长时还要核内分段 |

先过滤完整工作集超 UB 的候选，再比较并行度。预算用 byte：物理槽位按合法对齐取整，包含输入/输出队列及份数、FP32 中间量、融合 residual、常驻 gamma/scale、归约 scratch；只有生命周期不重叠且实现允许时才复用。预算与预留只扣一次。用 byte 算出的容量不能再乘 8 当元素数。Merge-row 的 Q=ceil(M/B_M)；独立二维块的 Q=ceil(M/B_M)×ceil(N/B_N)。核内 Split-R 不增加行任务；跨核 S 段才有约 M×S 个局部任务，之后还要合并。Q≥P 不是最优证明。

**五种条件策略**（须同时写不选它的理由）：

| 候选 | 值得对比时 | 放弃或另算的成本 |
|---|---|---|
| 跨核 Split-R | 独立行极少、行很长，batch/head/group 也无更多独立性 | 局部统计写回、全行合并、同步及额外启动。Softmax 用 m=max(m_s)，l=Σ l_s exp(m_s−m)，再算各输出；不能拼局部概率。mask、全无效行遵循原定义。 |
| 单核/少核 | decode 小行或总量很小，每核只能分到很短一段 | 减少碎片和初始化，不消除 launch；与多核及可行的融合基线比较。 |
| UB 局部转置 | 非连续轴归约，直接 ARA 效率不足且转置有复用 | 先比直接 ARA，再计转置指令、padding 和暂存。 |
| L2 外层分块 | 多遍访问，可把同一组任务的重读局限在外层块 | 输入大但只读一次不足以成立；核算竞争后的缓存容量、额外循环和拖尾。对齐到 cache line 不代表存在 L2 复用。 |
| 按有效长度分桶/调度 | 上游已有长度、工作确实可跳过无效区，且长短任务差异大 | 计入重排、索引恢复、排序和启动；切长 Softmax 仍须全行统计。 |

**可叠加机制。** 核间均衡与核内尾块分别处理；按 shape/dtype/layout 分派时保留回退。每核仅一轮通常没有双缓冲重叠机会；比较单双缓冲对 tile 大小和工作核数的影响。广播参数驻留与合并行、多缓冲共同占用 UB。prefill 先关注行并行；decode 先关注固定开销。注意 [1,64,128] 的逐 head RoPE 可能有 64 个任务，[1,8192] 的整行 RMSNorm 只有一个归约域。

**设计演练起点（不是硬件阈值）**

| 工作负载 | shape | 建议起点 | 优先比较的备选 |
|---|---|---|---|
| Prefill RMSNorm | `[2048,4096]` | 按行 Full-load，先核算融合后的 UB | 合适的行组、参数复用 |
| 短行 Softmax | `[8192,128]` | Merge-row | 不同 `B_M` 与 buffer 份数 |
| Decode RMSNorm | `[1,4096]` | 单核整行基线 | 融合 residual/后处理，比较固定开销 |
| 大词表 Softmax | `[1,131072]` | 核内 Split-R 基线 | 跨核 Split-R，计入完整合并成本 |
| 多行长 Softmax | `[128,131072]` | 按行分核、核内 Split-R | 根据实际 `P` 检查是否已足够并行 |
| 非尾轴 Softmax | `[32,1024,128]`，axis=1 | ARA，沿 `A₀` 切分 | `R` 全载或核内分段 |
| SwiGLU | 输入 `[1024,2,11008]` | 二维独立输出 tile | 单双缓冲、列块与尾块大小 |
| RoPE | `[1,64,128]` | 利用 token/head 独立性并保留旋转配对 | 多 head 合并；sin/cos 复用 |
| 逐 token 动态量化 | `[2048,4096]` | 按行统计并量化 | 多行合并；融合后放不下时分段 |
| 不均匀有效长度 Softmax | `[64,L_i]`，`L_i=128…8192` | 尊重有效长度的分派 | 长度分桶，前提是额外调度成本较低 |
