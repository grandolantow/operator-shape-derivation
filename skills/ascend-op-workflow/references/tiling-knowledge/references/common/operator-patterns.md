# 算子模式参考

以下整理 Add、Permute、SwiGLU、RotaryMul、DynamicQuant 的语义特征与候选方向。具体语义取自对应冻结规格，同名变体仍以当前原始规格为准。候选方向不是实测最优策略，不含固定切换阈值；可行性与成本按实际 shape、平台和原验证确认。无需建立家族或逐 case 映射记录。

## 逐元素广播（Add 类）

- 机制：两个（或多个）输入在广播语义下逐元素结合。影响选型的特征是**广播形态**（同形、行广播、
  标量广播、高维右对齐广播）与 dtype 宽度。
- 候选组织方向（假设，按影响选型的特征评估）：连续内层循环组织（同形/内层连续时）；广播侧索引
  展开组织（行广播时 inner stride=0 的访存模式如何影响循环结构）；小 shape 多行合并进单核
  循环。成本驱动：非广播侧的有效带宽、广播侧重复读取次数、尾块宽度。
- 边界：广播维度不通俗时索引计算本身的指令成本可能反超收益；尾部对齐影响每循环有效字节数。

## 布局重排（Permute/Transpose 类）

- 机制：纯布局搬移，无算术。影响选型的特征是**维度置换形态**（2D 转置、高维 swap、步长非连续输入）。
- 候选组织方向：分块局部性组织（把两个交换维放进同一 tile 以便连续访存）；GM 往返组织
  （UB 内无法高效换轴时经 GM 中转，流量翻倍须入账）；行/列向 DataCopy 参数组织。
  成本驱动：换轴后内层连续长度、碎片化搬运次数、对齐浪费。
- 边界：小矩阵分块收益可能被搬运固定开销吞掉；非 32B 对齐的内层段会改变有效带宽口径。

## 门控融合（SwiGLU 类）

- 机制（按原始规格）：**单输入** `x` 沿 `dim`（运行期参数，默认 -1）对半 chunk 为 `a, b`，
  输出 `silu(a) * b`，形状除 `dim` 减半外与 `x` 相同；`dim` 维大小必须为偶数。
  影响选型的特征是 **split 轴相对最内连续维的位置**（尾轴 chunk 时两半各自连续；非尾轴 chunk 时
  每个 outer group 沿 split 轴分成前/后半块，每块自身保留 inner 连续元素）、
  outer/split/inner 三个尺寸与 silu 中间舍入精度。
- 候选组织方向：尾轴 chunk 的两半连续段组织（同循环先载 a 半段、b 半段）；非尾轴 chunk 的
  同 outer group 前/后半块先后处理组织（每块 inner 段保持连续，跨块配对使访存模式不同，
  成本另评）；silu 中间精度的升/降档（升精度逗留成本入账）。
- 边界：silu 的数值实现精度属平台证据问题（见
  [api-precision-notes.md](api-precision-notes.md)），不在本卡断言；"相邻配对门控"
  等一般化变体不是本任务冻结输入的语义，不得当作允许的语义改写，如需支持必须显式声明超出
  冻结范围。

## 成对旋转（RotaryMul 类）

- 机制（按原始规格）：`output = input * r1 + rotated(input) * r2`；`rotated` 由 `rotary_mode`
  决定——`half` 模式取前后两半 `-x2, x1` 拼接，`interleave` 模式取最后一维相邻偶奇元素
  （下标 0::2 与 1::2 交叉）；`r1`/`r2`
  是**给定的系数张量**（与输入同为 4D、同 dtype 集合），随行广播复用；输入 4D，
  dtype 支持 fp16/bf16/fp32。**不生成 cos/sin，不做额外乘法或三角查表**。
  影响选型的特征是 `rotary_mode`（half 前后半分 vs interleave 最后一维相邻偶奇——决定配对重组
  方式）与系数广播形状。
- 候选组织方向：half 模式的前后半分段组织（两半各自连续，rotate 为段内符号交换）；
  interleave 模式的最后一维相邻偶奇重组组织（偶数下标/奇数下标提取与交错写回，
  访存模式不同，成本另评）；
  r1/r2 每核一次载入后随行广播复用（重复读取次数入账）。
  成本驱动：模式决定的配对重组搬运、系数复用效率、每元素两次乘一次加（固定语义量）。
- 边界：系数与输入的 dtype 提升路径按精度契约；`dim` 最后一维长度为奇数时 half/interleave
  的成对性破坏，属非法输入，须在分支条件中排除。

## 动态量化（DynamicQuant 类）

- 机制（按原始规格）：输入仅 `x`（`dst_type` 默认 int8）。per-token 语义按 dim=1/2（或全量）
  求 `max_abs`，`scale = (max_abs/127).clamp(min=1e-10)`，`quantized = round(x/scale)`
  `.clamp(-128,127).to(dst_type)`，双输出 `（quantized, scale）`。**scale 依赖完整 amax 归约
  结果：量化计算必须在归约完成之后进行**——即使 x 一次 GM 载入后常驻 UB，计算上仍是
  "归约阶段 → 量化阶段"两个先后阶段；区分**访存趟数**（GM 载入一次的驻留设计合法）与
  **计算阶段**（不得宣称同步在线计算）。
- 候选组织方向：一趟 GM 载入 + UB 归约→量化两阶段组织（x 驻留，amax 完成后原地量化）；
  两趟 GM 组织（amax 趟 + 量化重读趟，重读流量按
  [resource-lifetime.md](resource-lifetime.md) 入账）；scale 写出组织
  （每行/每 tensor 一份 scale 的写放大另列）。成本驱动：归约遍历、量化遍历、round/clamp
  指令量（固定语义量）、scale 输出量。
- 边界：`smooth_scales`/`group_index`/非默认 `dst_type` 等变体**超出本任务冻结输入范围**，
  须显式标注为未覆盖/未测，不得默认已测；amax 为零或极小时的 `clamp(min=1e-10)` 防零除
  属规格语义；round/clamp 的舍入口径属精度契约，不得按假设的硬件行为填写（证据等级见
  [api-precision-notes.md](api-precision-notes.md)）。

## 组合模式注意事项

- 以上模式可叠加（如 Permute 输入的 DynamicQuant）：按实际主计算机制分析，叠加机制的开销一起比较，不为数量增加分支。
- 本卡不设任何固定阈值、不强制多 kernel 或满核；一切可行性回到账本与真实成本区间。
