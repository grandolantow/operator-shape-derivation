# 运行期开销与缓存正确性

涉及参数发布、重排、缓存、多阶段 kernel 或测量口径时按需阅读；在原设计和性能说明中分析相关项，无固定字段交付。

tiling 决定的不只是核数和 tile：从"host 决定参数"到"device 开始计算"之间每一步都有成本，决策与性能结论必须把它们显式区分，不能默认为 0，也不能伪精确。

## 1. 可选成本分析维度（展开与候选有关的项）

| 成本项 | 内容 | 常见误判 |
|---|---|---|
| launches | kernel/任务启动次数（含拆分引入的第二次启动） | 只算主 kernel，忘掉分阶段统计/合并的第二次启动 |
| GM 读写 | 各阶段读写字节数（含重读、写回中间量、参数下发） | 只算输入+输出；忽略 SplitD 第二遍重读 |
| compute | 向量指令规模与循环层数（含升精度转换） | 只算主运算，忘掉 cast/reduce 指令 |
| workspace | 全局工作区字节数与读写次数 | 声明分配但忘算读写成本；或未知就填 0 |
| sync | 核间/阶段同步、事件等待、队列出队阻塞 | 认为同步免费；或假设任意屏障可用 |
| runtime preparation | 平台查询、参数求解、tiling 数据发布、H2D 拷贝、内存/队列分配初始化、必要的清零 | 全部当作免费或全部算进 kernel 时间 |

## 2. 平台查询与分配

- SoC、核数、UB 容量、对齐粒度来自本轮平台查询（`npu-arch` / `platform_ascendc` 接口），查询命令与输出存入任务证据；文档示例常数不是查询结果。
- Host 侧每次执行可能的成本：平台信息查询、tiling 参数求解、tiling 数据（TilingData/tiling info）向 device 发布、输入 H2D（若工作流涉及）、workspace 分配与必要的清零、stream/queue 创建。它们在不同调用阶段发生的次数不同（见第 4 节），决策时按阶段分别说明，不要用单一常数。
- 分配复用（如 workspace 由运行时缓存）必须以可查证的机制为准；无法查证时按"每次分配"保守申报，并列入决策不确定性。

## 3. 缓存正确性（如实现含 host 侧缓存）

无通用缓存实现；任何缓存必须同时满足：
1. 绑定正确的 device；
2. 绑定完整配置（tiling 参数、attr、dtype、layout）；
3. 输入值变化不影响可缓存的部分、影响的部分必须失效；
4. 绑定正确的 stream/队列上下文；
5. 生命周期安全（缓存的 buffer 在使用期间不被释放或改写）；
6. 如实现涉及图捕获与重放，使用正确配置及生命周期内的资源；缓存只能在真实初始化成功后发布，捕获期临时状态不能被误当作已完成初始化。
以上任一条无法核证时，禁止宣称"已缓存安全"，按未缓存保守处理并记录。

## 4. 冷启动 / eager 稳态 / 图模式

三类阶段的成本结构不同，不能混测或混报：
- 冷启动：含模块加载、平台查询、编译/加载 kernel、首次分配。
- eager 稳态：重复调用，主要剩参数求解、tiling 发布、启动与同步。
- 图模式：捕获期与重放期成本不同；捕获期的一次性成本不得摊进重放期结论。
报告必须注明结论属于哪一阶段；比较两条实现时必须同阶段比较。

## 5. 结论分离（验收措辞约束）

以下五类结论各自独立，不得互相替代：
1. 正确性：精度与边界通过；
2. 适配性：不同 shape/dtype 走到了声明的分支（由实际源码与原验证结果支撑）；
3. 资源合法性：UB/workspace/队列账本不超；
4. 绝对耗时：本轮各 shape 的实测时间（含阶段说明）；
5. 相对收益：与基线的配对比较。
没有可比基线时，允许报告绝对耗时与适配性证据，**禁止**宣称"验证过的加速"或"无回归"；"未观察到退化"只有在配对测量存在时才可写。与选型及实现核对的衔接见 [shape-selection.md](shape-selection.md)。本参考不增加专项测试流程。
