# 证据与 shape 推导

## 从材料到字段

每条决定 shape 的事实记录 source id、文件/键/行范围或 trace event 定位及适用条件。为读取的关键配置、源码片段、权重头或采集文件保留哈希；代码有 revision 时同时记录。哈希证明所用材料，不能证明服务加载了该代码版本。

权重默认只读取配置、索引和 tensor header 等元数据；不为 shape 推导加载完整大模型。分别记录 checkpoint 的存储 dtype、loader 变换和目标接口 dtype。模型级量化标签不能替代逐张量证据。

不要设定“profiling 永远高于源码”或相反的固定优先级。冲突时检查设备/版本、进程所用代码、执行阶段、量化方式、padding、包装层、张量视图和采集点；未解释的冲突保留并限制结论适用范围。

关键字段可采用以下状态，按字段记录来源，避免整个 case 一概标成“已观测”：

| 状态 | 含义 |
|---|---|
| observed | 在明确运行条件下直接观测到该字段 |
| derived | 由有来源的参数和公式得到；列出依赖与前提 |
| assumed | 为测试选定的值；列出理由与使用范围 |
| unknown | 当前不能确定；列出缺项并保留符号或 null |

推导值依赖假设时，必须保留这条依赖链，不能消除 assumed 属性。未知的频率、延迟、cache 容量等使用 null，不能用 0 冒充观测。

## 执行量与人工判决

在首次代入公式前，将影响目标 shape 的执行量接到结构化结果。每个量说明：当前值或 unknown/conditional、具体范围（如某次调用/某 DP rank/某个输入轴）、来源，以及派生规则和假设依赖。名称按目标选择；普通 MatMul 可只有 M/K/N，无需增加 DP、prefix、cache 字段。保留“原始字段 → 范围解释/转换 → 生效值”，同名字母不代表同一范围。

- `batch_per_dp = batch_global / DP` 只在用户已选择、调度证据已确认或已明确获准采用均匀分配假设时成立。一般允许按 rank 的不均匀分配；全局总量与 DP 数本身不足以得到本 rank 值。
- 区分逻辑有效量与实际执行/分配量。没有图桶、同步或调度信息时，实际执行 token 可以未知；不把逻辑 token 直接标为实际执行 token。与目标无关的未知量不阻塞其他结果。
- 派生链传递假设和未知。已知维度不得依赖尚未解决的量却隐藏条件；公式异常、缺失分支或不适用时保留 unknown/conditional，不回退旧值、示例值或默认均分。
- 参数口径的不同解释会改变目标 shape，且现有材料不能判定时，**立即向用户说明具体风险并提出待判问题**：哪个字段/范围不明、不同解释影响什么、需要哪个决定或证据。记录 pending decision 与受影响的量；等待期间仅继续独立部分。不能只在最终报告写“存在假设”后导出受影响的 runnable case。
- 已有明确人工选择/允许的具体假设可直接沿用并记录来源，不重复申请；“没有 profiling”不自动授权未说明的运行分配。不能从用户未回复推断同意。若只分析符号关系，保留条件分支即可；需要具体化时再完成对应判决。

规则选对与实现正确分别验收：

| 问题 | 可用证据 | 不足以单独证明它的检查 |
|---|---|---|
| 当前接口是否复制、分片、padding、裁剪或切分 | 当前源码调用及实际参数/接口、参数创建、可用的独立观测；确认适用版本/分支 | 自己写的公式、参数变化测试、schema通过 |
| 已选规则是否正确实现和传播参数 | 调用实际推导函数的预期关系检查、阈值两侧/边界、确定性重算 | 仅重复声明关系或复制同一错误公式 |

## 单算子与组合目标

列出外部输入/输出、常量/权重、可写状态、metadata 与内部边；每条边明确生产者和消费者。

对 A、B 组合成 C，核对：

- 串联、并行分支、共享输入、结果合并的实际语义。A+B 是任务表达，不能当成数学定义。
- 输入绑定及轴含义；reshape 的元素数、转置轴、广播规则、reduce 轴和 keepdim、split/concat 的轴与长度。
- 中间 dtype、量化 scale/zero-point、打包、view/contiguous 转换。最终 output dtype 不能代替中间计算约定。
- 哪些中间张量保留为 C 的输出，哪些内部消除；保留用户明确要求的输出和状态副作用。
- A、B 既有实现的合法形状交集。若 C 尚无实现，区分语义约束、复用既有实现的约束和新设计假设；不要将独立 A、B 的所有 tiling 限制无条件强加给未来 C。

仅影响内部 kernel 调度且不改变接口的设计，不应使 shape 推导膨胀为 kernel 实现任务。

## 逐调用点的张量契约

对存在包装层、多次调用或不同执行布局的目标，以 `operator_id + callsite/variant + boundary + tensor/argument` 定位张量。先确定本行代表公开接口、wrapper 内部 view、底层 kernel 实参还是持久状态，再写 shape/dtype；名称相同不是合并依据。

按目标需要记录以下信息，不要求简单算子填无关字段：

- **调用与完整参数**：定位实际调用及注册/binding，列实传 tensor、标量、可选参数、可写 out buffer 和返回值。记录 `present_when` 与返回/原地修改关系；`None`、空 tensor、未采集和未知是不同状态。kernel 内部辅助输出不自动成为 wrapper 返回值，wrapper 额外返回值也不能因主 kernel 未显示就删除。
- 声称精确公开接口时，将参数集合（含非 tensor 参数）与真实函数声明/注册 schema 逐项核对；可解析的 Python 签名可用 AST 提取。内部 metadata、implementation 返回值和 wrapper 返回值使用各自的 boundary/role，不共用公开参数边界。注释中写对签名不能抵消表格字段的矛盾。
- **逐边 dtype**：从分配/创建、索引或归约结果，沿 cast、copy、view 到消费者核对。分开记录 checkpoint storage、原生算子结果、持久 buffer 和对外返回类型。不能凭“索引通常是某类型”或模型量化标签批量补 dtype；证据缺失就保留 unknown。
- **执行轴的来源**：每条 token/row 轴绑定生产者及当前执行阶段。分片、补齐、gather、裁剪、dispatch 后分别定义作用域；同一模型不保证所有层共用一个 T，某模型消费的输入也可能来自另一模型。检查非整除与小于并行度的分支，不默认只用整除样本。
- **多次调用**：同一 routing、排序、归一化或 finalize 接口可能有不同参数和语义。分别列调用条件、输入输出行轴、可选权重和逆变换；不为匹配一次局部调用而改写全局参数。
- **buffer 与 view**：分开记录传入分配 shape、有效 shape、alias/source tensor 和影响接口的 squeeze/unsqueeze/reshape/stride。只有源码或观测支持时才断言别名；只有逻辑 shape 时不冒称物理布局已验证。未知容量可以保留符号，不妨碍已知有效轴的推导。
- 沿目标结果追踪到交给消费者的 return/view 或可写 out；持久 buffer、循环内更新和最终返回的切片分别记录。若该出口不在本次范围，明确说明，不能用内部 buffer 记录代替完整输出契约。

跨行核对时，同一 tensor 的生产者输出与消费者输入应在记录的变换后满足 shape、dtype 和状态关系。将张量来源、调用分支和转换作为可检查的字段，避免由消费者所在模块的统一上下文覆盖输入来源。

## 布局边界与执行轴传播

目标涉及序列/行分片、补齐、collective 或跨模型输入时，将相关变换接成可追踪的数据流；不要求没有这些变换的简单算子建立额外表格。

- 每条发生布局变化的边记录输入/输出 tensor id、轴位置及语义、变换与生效条件、并行组/大小、规则来源。沿用已有 schema 即可；规则来源与运行参数来源分开记录。包装层的 unsqueeze/transpose 后，token 轴不一定是第 0 维。
- 沿已核实的调用链区分完整、补齐、本地分片、collective 输出和有效裁剪后的行数。只有源码规定“补齐至并行度的倍数后等分”时才使用相应 ceil 关系；不能把 all-gather 输出直接记为未补齐的有效 T，也不能将 TP 大小当成已开启 SP 的证据。
- 按张量的生产位置应用规则：切分前的入口/初始 residual、层内 residual、归约前后以及 gather 后的消费者分别核对。不能按 residual、hidden、draft 等名字批量替换 T；主模型上下文被草稿消费时仍绑定原生产者的执行范围。
- 同时追踪残差支路和算子主支路，到重新汇合或目标出口为止。归约不涉及 token 轴时保留该轴所属范围；它不会自动恢复全量 token。每个分支都注明成立条件，条件未知时保留 conditional，不默认走全量或分片路径。
- 将轴关系落实到实际推导函数及导出字段。调整原始 T/并行度时，只改变依赖它且满足分支条件的轴；禁止通过全局上下文覆盖、按目标前缀统一替换，或新增自由参数逐张量拟合实测值。
- 观测比例吻合只支持候选解释。找不到对应的源码变换时，记录观测事实、缺失的调用边界和受影响 tensor id；保持原静态结论与观测层分开。允许按用户要求做假设模拟，但不得改称源码已定位或独立预测成功。

## 需要分开的维度层次

1. 模型常量：hidden/head/intermediate/expert/压缩维度及版本适用性。
2. 请求与执行：client 并发、每 rank 实际 batch、query/prefix 长度、prefill/decode/mixed、speculation、并行切分与同步。
3. 分配与执行容量：token budget、graph buckets、padding、cache/page/table、输出分配上限。
4. 有效工作量：有效 token/输出行、routing group counts、mask、接受/保留条目和实际读写范围。
5. 物理接口：kernel 看到的 shape、dtype、stride、storage offset、layout/format、packing/对齐及别名。

只分析影响目标接口的层次。不能将 client 并发直接当本 rank batch；不能由容量反推实际 workload，也不能由其他 rank 的原始 token 数替代同步后的执行结果。

对 packed 低位类型同时记录逻辑元素数、物理 storage shape 和解释方式。stride/offset 写清单位；不将 byte stride 与 element stride 混用。轴名应表达含义，而非沿用不同算子的同名字母。

对 ragged、MoE、cache、state 类接口，把元数据当作 shape 契约的一部分：prefix sums、group_list、start positions、block table、有效长度、padding masks 等需满足相关联的不变量。位置/路由变化可能改变工作量，即便 tensor shape 完全相同。

## Profiling 的使用边界

先识别采集覆盖的阶段、rank/step/layer 范围及缺失字段。通过关联 id、调用链和事件参数定位目标实例；同名 kernel 不必是同一算子，不同 kernel 名称也可能实现同一接口。

核对运行配置、源码版本、并行组与采集开关。脚本、冻结源码和 profile 之间尚无同次运行证据时，不宣称配置已对齐。仍可检验不依赖取值的 dtype、轴含义、分支、输入角色及数据流关系；容量/并行度等数值差异单列，不强行计算端到端准确率。若从 profile 反推参数再代入，标为观测实例化，不能当作独立预测命中。

源码完整性按当前目标的实际入口/注册、调用者、后端或 binding 检查；文档宣称支持、相关算子已合入或存在近似版本目录，均不能单独证明模型调用链已齐全。路径或运行版本未对齐时，只阻止受影响项被标为已验证及其未经授权假设的 runnable 导出；保留条件推导、已确认子路径和具体补充材料清单，不要求无关任务全局停工。

每个比较项保存唯一 tensor/argument id、调用边界、核对字段、源码定位和原始记录定位，并判为一致、不一致、不可比或未观测。空字段/缺少指针不单独证明空 tensor 或可选参数为 None；与源码一致的解释也不能升级为运行时直接观测。

统计时分别报告 shape、dtype、接口覆盖/可选性、布局/状态，给出唯一张量项的分子、可判定分母、总目标数和 checked coverage；重复 kernel 事件次数另计。核对部分张量不等于整个算子通过，同组一个字段失败也不等于全部关联算子失败。配置假设调整后的比例只能标为条件分析，不称实测准确率。

比较“仅代码”和“加入 profiling”时，分开统计符号关系的验证与完整数值 shape 的验证，保留原输入、规则和逐项状态。列出共同子集、新增可判定项及未知项；已知 rank/轴的明确冲突仍须单列，不能因其他轴未知而隐藏。少量固定维度的全对不等于全量公式准确；采集提取的 T/分支条件不得计作纯静态证据，看过观测后的修订与回顾性模拟不得计作独立 skill 成功率。

有输入维度记录才能将其标为 observed shape。若只有耗时，可用于已匹配目标的热点排序；不据此补造维度、dtype、stride 或输入值。输入形状记录也通常不足以复原 group_list、block table 等动态 metadata。

聚合时记录样本计数、分母、权重定义以及已去除的 warmup/重复/无关区间。跨 rank 或重叠事件的耗时不能直接作为端到端收益相加。样本内频率不能无条件推广到生产流量。

## 用例选择

按目标分支选择最小/代表/大规模、对齐与尾部、边界两侧、变长/不均衡及 padding 场景。只有接口允许时才加入零长度；有效输出为零的状态更新场景不一定等于空调用。

区分性能代表性和约束覆盖，按实际需要组合。使用观测分布时保留选取/合并规则和覆盖率的分母。缺少 profiling 且用户已确认没有时，从已知配置范围内选择场景；没有依据的上下限也标明假设。

不穷举全部参数笛卡尔积。需要硬件、dtype 或布局全覆盖时明确用户要求与用例预算；精简集合不能冒称完整覆盖。
